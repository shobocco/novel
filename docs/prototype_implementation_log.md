# プロトタイプ実装・追加改修記録

## 1. 文書の目的

本書は、「残クレバハムートで魔王討伐」の初回プロトタイプ実装から、その後の画面確認を通じて追加・変更した内容をまとめた実装記録である。

現時点のゲームは、ビルド作業を行わず `game/index.html` をブラウザで開いてプレイできる。

---

## 2. 初回プロトタイプ実装

### 2.1 ノベルゲームエンジン

`scenario/*.json` を読み込み、JSON内の命令を順番に実行するデータ駆動型エンジンを実装した。

主な対応命令：

- `dialogue`
- `narration`
- `background`
- `showCharacter`
- `hideCharacter`
- `hideAllCharacters`
- `showEnemy`
- `hideEnemy`
- `choice`
- `set`
- `add`
- `subtract`
- `setFlag`
- `condition`
- `conditionFlag`
- `jump`
- `loadScenario`
- `battle`
- `reward`
- `loanPayment`
- `appraisal`
- `ending`
- `statusMessage`
- `effect`
- `wait`
- `document`

未知の命令はゲームを停止させず、コンソールへ警告を出して次へ進む。

### 2.2 基本画面

- 16:9基準のゲーム画面
- 背景画像
- 左・中央・右のキャラクター立ち絵
- 画面下部のメッセージウィンドウ
- キャラクター名表示
- 選択肢ボタン
- CONTRACT STATUS
- タイトル画面
- エンディング専用画面
- デバッグパネル
- 狭い画面向けの簡易レスポンシブ対応

### 2.3 テキスト進行

- クリック、Enter、Spaceで進行
- 文字単位のタイプライター表示
- タイピング中の入力で全文表示
- 全文表示後の入力で次のstepへ移動
- 選択肢・演出・戦闘中は通常のテキスト送りを無効化

### 2.4 シナリオとエンディング

既存の第一章から第十章、NORMALルート、GOODルート、エンディングシナリオを接続した。

到達可能なエンディング：

- NORMAL END
- GOOD END
- BAD END A（ローン支払い不能）
- BAD END B（最終査定不足）
- BAD END C（最終戦敗北）

## 3. 画像表示の改修

### 3.1 同一キャラクターの重複防止

同じキャラクターを別位置へ再表示する場合、旧位置の画像を削除してから新位置へ表示するよう変更した。

これにより、神様などが左右や中央へ移動した際に複数表示される問題を解消した。

### 3.2 章・シナリオ移動時の立ち絵消去

別シナリオファイルへ移動する際は、前シナリオの立ち絵と敵画像を消去する。

受付嬢など、前の場所にいた人物が次の背景へ残らないようにした。

### 3.3 画像フォールバック

指定された表情画像がない場合：

1. `*_normal.png` を使用
2. normal画像もない場合はCSSプレースホルダーを表示

不足画像は `Missing asset:` としてコンソールへ記録する。

### 3.4 立ち絵位置

左・中央・右の全立ち絵を同じ割合で下へ移動し、キャラクター間の高さを統一した。

- PC：下方向へ30%
- 狭い画面：下方向へ14%

下側はメッセージウィンドウの背後へ入ることを許容している。

### 3.5 敵画像

敵専用レイヤーを追加した。

- ゴブリンを中央表示
- オークを中央表示
- 主人公立ち絵のおよそ半分の高さ
- セリフウィンドウより上へ配置
- 敵表示中は主人公・バハムートなど味方立ち絵を非表示
- 戦闘終了時に敵画像を非表示
- セーブ／CONTINUEでも敵表示状態を復元

---

## 4. 場面転換と章タイトル

### 4.1 背景トランジション

黒画面を挟む暗転方式を廃止し、旧背景から新背景へ直接クロスフェードする方式へ変更した。

処理順：

1. 次の背景画像を事前読込
2. 旧背景を保持
3. 新背景へ変更
4. 旧背景をフェードアウト
5. トランジション完了後に立ち絵とタイピングを開始

### 4.2 章タイトル

- 章タイトル中は各ゲームUIを非表示
- メッセージ、ステータス、SAVE、立ち絵、敵、選択肢、通知、デバッグパネルを隠す
- 章タイトル表示中に次の背景を事前設定
- 章タイトルはフェードせず即時表示
- 背景は最初から薄く透ける
- 透明度は表示中に変化しない
- タイトル消去後に背景・立ち絵・本文を開始

### 4.3 ルート名表示の削除

以下のルート用タイトル表示を廃止した。

- `NORMAL ROUTE 魔王討伐`
- `GOOD ROUTE 神様討伐`

「魔王を倒す」「魔王を信じる」の選択後は、直接次の場面へ移動する。

## 5. CONTRACT STATUS

### 5.1 表示開始条件

CONTRACT STATUSは、契約フラグ `signedContract` が成立してから表示する。

- 契約前：非表示
- 契約後：表示
- CONTINUE：保存された契約フラグから復元
- バトル中：非表示

### 5.2 表示内容

- 所持金
- 次回支払額
- 返済回数
- バハムートの状態
- 信頼
- 査定予想

### 5.3 査定予想

査定予想と最終査定は同一の計算式を使用する。

```text
最終評価 =
bahamutValue
+ 状態補正
+ 信頼補正
+ 酷使ペナルティ
```

ランク：

- S：90以上
- A：80以上
- B：70以上
- C：55以上
- D：55未満

---

## 6. 報酬・ローン・査定

### 6.1 報酬演出

報酬獲得時は以下を大きく表示する。

```text
QUEST CLEAR
報酬名
+金額 G
```

### 6.2 ローン支払い

ローン判定は `loanPayment` step実行時だけ行う。

- 支払い可能：所持金減算、返済回数加算
- 支払い不能：BAD END A
- 支払い前後の金額を強調表示
- 請求書画像をモーダル表示可能

### 6.3 査定バランス

酷使ペナルティ：

- 使用0〜1回：0
- 使用2回：-5
- 使用3回：-20
- 使用4〜5回：-25
- 使用6回以上：-35

ゴブリン・オーク・魔王の3戦すべてでバハムートを使った場合、「低危険度の依頼を自分主体でこなす」を選んでも評価66となり、BAD END Bへ進む。

同条件で使用2回までなら評価81となり、査定に成功する。

## 7. RPGバトルシステム

### 7.1 共通仕様

ゴブリン、オーク、魔王、神様の戦闘をHP制ターンバトルへ変更した。

表示内容：

- 主人公HP
- 主人公レベル
- 主人公攻撃力
- 敵HP
- ターン数
- HPゲージ
- 戦闘ログ
- コマンドボタン

コマンド：

- 剣で攻撃
- 防御
- ポーション
- バハムート

勝敗に乱数は使用しない。

### 7.2 主人公の成長

初期値：

```text
LV 1
最大HP 30
攻撃力 8
```

勝利時の成長：

| 戦闘後 | レベル | 最大HP | 攻撃力 |
|---|---:|---:|---:|
| 初期 | 1 | 30 | 8 |
| ゴブリン撃破 | 2 | 35 | 10 |
| オーク撃破 | 3 | 40 | 12 |

レベルアップ時は成長結果を画面へ表示する。

成長値はセーブ対象であり、古いセーブから最終戦へ進んだ場合は、物語上の最低値としてLV3・HP40・攻撃力12を補完する。

### 7.3 ゴブリン戦

```text
ゴブリンHP：26
反撃：5
防御時：2
```

- 通常攻撃で4ターン勝利
- 防御だけを続けると敗北
- バハムート使用時は26ダメージで一撃撃破
- バハムート状態を5消費
- バハムート戦闘回数を1加算

### 7.4 オーク戦

オーク戦は `bg_road` の背景を維持したまま開始する。

```text
オークHP：40
反撃：6
防御時：2
```

- 成長後の通常攻撃で攻略
- バハムート使用時は40ダメージで一撃撃破
- バハムート状態を8消費
- バハムート戦闘回数を1加算

### 7.5 魔王戦

```text
魔王HP：60
反撃：8
防御時：3
バハムート攻撃：24
```

LV3・攻撃力12の場合、通常攻撃だけなら5ターンで辛勝する。

主人公のHPが0になるとBAD END Cへ進む。

### 7.6 神様戦

神様戦のみ、主人公・バハムート・魔王の三者共闘となる。

```text
神様HP：150
反撃：12
防御時：4
バハムート自動攻撃：18
魔王自動攻撃：14
```

ターン順：

1. 主人公の選択行動
2. バハムートが自動攻撃
3. 魔王が自動攻撃
4. 神様が生存していれば反撃

神様戦では手動のバハムートコマンドを無効化し、「仲間が自動攻撃」と表示する。

戦闘中は主人公・バハムート・味方側の魔王立ち絵を隠し、敵である神様のみを表示する。

## 8. セーブ／CONTINUE

`localStorage` を利用して以下を保存する。

- `gameState`
- シナリオファイル
- scene ID
- step番号
- 現在の背景
- 表示中のキャラクター
- キャラクターの位置・表情
- 表示中の敵
- 主人公の成長値

CONTINUEは必ず通常モードで開始し、デバッグパネルを表示しない。

旧形式のセーブに視覚情報がない場合、現在sceneの先頭から保存stepまでの表示命令を解析し、背景と立ち絵を可能な範囲で復元する。

## 9. デバッグ機能

DEBUG START時のみデバッグパネルを表示する。

表示項目：

- ゲーム状態
- 所持金
- バハムート価値
- 状態
- 信頼
- 戦闘回数
- ルート
- フラグ
- 現在のシナリオ、scene、step

操作：

- 所持金 +100,000 G
- 価値 +10
- 状態 +10
- 信頼 +10

通常のGAME STARTとCONTINUEでは非表示となる。

## 10. 直接起動とキャッシュ対策

### 10.1 `file://` 対応

ブラウザのローカルJSON・ES Modules制限を回避するため、以下の直開き用ファイルを生成している。

- `game/js/scenario_bundle.js`
- `game/js/game_bundle.js`

JSONファイルとモジュールソースを正本とし、バンドルへ同期している。

### 10.2 GitHub Pagesのキャッシュ対策

ページ読込時にタイムスタンプを生成し、以下のURLへクエリー文字列として付加する。

- CSS
- JavaScript
- JSON
- 背景画像
- キャラクター画像
- 敵画像
- 書類画像

例：

```text
game_bundle.js?v=読み込み時刻
```

同じページセッション中は共通のタイムスタンプを使う。

タイトル画面表示中にシナリオJSONを解析し、実際に使用される以下の素材をバックグラウンドで読み込む。

- ゲーム内テキストのマウス選択を無効化

## 13. NORMAL ENDの改修

NORMAL ENDでは、残価精算成立後にバハムートを神様へ返却する。

流れ：

1. 魔王討伐
2. 最終査定成功
3. バハムートを残価精算のため返却
4. 主人公が一人で街へ帰る

主人公の台詞：

```text
……終わった。本当に、今回はひどい目にあった。

けど、これで自由だ。街に帰ろう。
```

GOOD ENDでは契約そのものが消滅するため、バハムートは主人公の相棒として残る。
